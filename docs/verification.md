# 검증 기록

2026년 9월 13일 로컬 Windows 환경에서 확인했어요. 아래는 초기 v1.0 검증 기록이며, 확장판 검증은 다음 항목에 별도로 기록해요.

- `npm test`의 물리·재난·전체 캠퍼스·GLB 가져오기 검사 46개 통과
- `npm run build`의 TypeScript 검사와 배포용 빌드 통과
- 저장된 GLB를 Three.js GLTFLoader로 다시 열어 부재 수, 지지 연결 ID, 유한한 장면 범위 확인
- 브라우저에서 기본 운석 실행 후 본관 일부 붕괴와 잔해 낙하 확인
- 전체 구조 상태 100%로 초기화, 일시정지 시 시뮬레이션 시간 고정 확인
- 재난 분류와 선택, 속도 조절, 정면·전체 카메라 확인
- 지진해일 실행과 침수 후 구조 붕괴 확인
- 브라우저의 현재 장면 GLB 저장 완료 확인
- 기본 1280×720 화면과 390×844 화면에서 조작 패널·캠퍼스 표시 확인
- 브라우저 콘솔에 실행 오류 없음

전체 캠퍼스 통합 시험에서 기본 운석에 해당하는 충격은 673개 부재 중 83개를 즉시 분리하고, 3초 뒤 178개로 붕괴가 진행됐어요. 떨어진 날개 쪽 345개는 모두 연결된 상태를 유지했어요. 이 결과는 게임 내 구현을 검증한 것이며 실제 학교의 피해를 나타내지 않아요.

## v1.1 강도·세부 설정 확장

2026년 9월 13일 같은 환경에서 확장판을 확인했어요.

- `npm test`의 6개 파일, 153개 검사 모두 통과
- `npm run build`의 TypeScript 검사와 배포용 빌드 통과
- 재난 14종의 세부 항목 74개가 실제 화면·물리 동작을 바꾸는지 검사
- 실제 재난 실행 경로로 기본 크기·재질의 운석을 강도 20에서 실행해 구조 부재 95% 이상 분리, 여러 구조 조각이 원래 위치에서 수평 거리 100m 이상 이동하는지 검사
- 브라우저에서는 같은 최대 강도 운석 실행 후 673개 부재 전체 분리와 캠퍼스 바깥으로 비산하는 잔해 확인
- 강한 충격을 반복해도 위치·속도가 유한하고 빠른 조각이 지면을 관통하지 않는지 검사
- 재난별 최대 설정의 종료·자원 해제, 독립된 해일 진행 방향, 운석 수직 낙하, 비행기 기수 방향, 높은 곳에서 떨어지는 짧은 우박 재난 확인
- 토네이도 상승력 0에서 수직 힘이 사라지고 기본값에서는 기존 동작을 유지하는지 검사
- 운석 지름 12m·철질·속도 90m/s·X 좌표 −10 입력 후 재난 전환과 새로고침으로 값이 복원되는지 확인
- 재난마다 별도 설정 유지, 실행 시 설정 복사, 숫자 입력의 Enter 확정, 현재 재난 설정 초기화 확인
- 1280×720과 390×844 화면에서 설정 창의 스크롤·숫자 입력·고정 실행 버튼 확인
- 배포용 미리보기에서 강도 20 및 세부 설정 표시, 재난 실행 전 캠퍼스 안정 상태, 콘솔 실행 오류 없음 확인

## 2026년 9월 19일 캠퍼스 배치 보완

- 사진 비율에 맞춘 운동장과 동쪽 코트, 운동장 밖으로 이어지는 기숙사, 뒤쪽 창의융합동 연결부를 상공·전체 보기에서 확인했어요.
- 추가 건물의 파괴 가능 여부, 지지 부재 ID, 운동장과의 겹침, 정지 상태 안정성, 재난 후 초기화를 검사했어요.
- 물리 부재 1,662개를 포함한 GLB를 다시 내보내고 재수입 검사와 배포 빌드를 통과했어요.
- 브라우저 실행 오류는 없었어요. 이후 요청에 따라 비주얼을 유지하는 범위에서 성능 최적화도 진행했어요.
- 최대 강도 운석 통합 시험은 같은 9초의 가상 시간을 더 많은 부재로 계산하므로 이 시험만 실행 제한을 30초에서 60초로 늘렸어요. 피해 비율·비산 거리 기준은 그대로 유지했어요.

### 비주얼을 유지하는 최적화

동일한 확장 캠퍼스에서 최대 강도 운석으로 가상 시간 9초를 진행하는 로컬 프로파일을 비교했어요. 초기 정지 구간은 3초예요. CPU 처리 시간은 측정 당시 실행 환경에 영향을 받으며, 브라우저 FPS 향상률을 뜻하지 않아요.

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 전체 장면 그리기 호출 수 추정(그림자 제외) | 2,914 | 2,419 |
| 삼각형 수(인스턴스 포함) | 230,083 | 230,083 |
| 정지 구간 CPU 시간 | 122ms | 11ms |
| 최대 운석 구간 CPU 시간 | 26,736ms | 16,904ms |
| 물리 부재 수 | 1,662 | 1,662 |

불투명 배경 장식만 같은 재질·그림자 속성·공간 구역별로 합쳤어요. 지면은 높은 장식과 분리해서 굴착 표시가 유지되도록 했어요. 지형 생성은 동일한 절삭 상태에서 재사용하며, 높이는 수평 격자마다 한 번만 계산해요. 지형 해상도와 삼각형은 줄이지 않았어요. 멈추거나 소멸한 잔해의 중복 갱신, 차가운 부재의 열 계산과 불꽃 확인용 좌표 조회를 줄였어요. 물리 시간 간격, 충돌 정밀도, 그림자 해상도, 입자 수는 유지했어요.

선택 프로파일은 PowerShell에서 환경 변수 `CBSH_BENCHMARK=1`을 설정한 뒤 `npm test -- tests/performance-profile.test.ts`로 실행할 수 있어요. 일반 테스트에서는 이 프로파일을 건너뛰어요.

최종 전체 검사에서는 179개 테스트가 통과했고, 선택 실행용 성능 프로파일 1개는 건너뛰었어요. 프로파일은 별도로 실행해 통과했어요. 브라우저에서 일반 운석 이후 국소 붕괴·잔해 안정화와 전체 초기화를 확인했으며 실행 오류는 없었어요.


## 2026-09-19 파괴 균형과 직접 잡기

- 전체 테스트 184개 통과, 선택 실행 성능 프로파일 1개 건너뜀. TypeScript 검사와 프로덕션 빌드 통과.
- 마우스로 부재를 잡아 옮기기, 잡은 지점에 힘 적용, 놓은 후 낙하, 지지 구조 붕괴, 초기화 시 잡기 해제를 검증했다. 브라우저 드래그에서도 부재 분리와 고정된 카메라를 확인했다.
- 최대 강도 10에서 구조가 일부 남고 잔해가 비산하는 조건, 빠르게 날아가는 잔해를 제외한 제한 발화, 지면 굴착 켜기/끄기, 깊은 구덩이 내부 낙하와 중복 굴착 생략을 검증했다.
- 브라우저에서 기숙사 지붕에 다양한 불꽃과 불투명한 회색 구체 묶음 연기, 운동장에 아래로 파인 지형을 확인했다.
- 연기 인스턴싱과 국소 지면 마스크 갱신으로 반복 작업을 줄였다. 이번 변경의 FPS 향상률은 별도로 측정하지 않았다.


## 2026-09-19 직접 조작·연소·용암 개선

- 전체 테스트 190개 통과, 선택 실행 성능 프로파일 1개 건너뜀. TypeScript 검사와 프로덕션 빌드 통과. 다운로드 모델도 교내 포장 조각을 포함해 1,941개 부재로 다시 내보냈다.
- 좌클릭은 선택한 일반 재난 실행 또는 직접 파괴, 우클릭 드래그는 회전, 휠 클릭 드래그는 이동, 휠은 확대·축소로 배정했다. 직접 파괴 활성화 토글을 없애고, 누르기 반복 적용과 연소 드래그 경로 보간을 연결했다. 브라우저에서 좌클릭 실행, 우클릭 시 피해 없음, 휠 확대를 확인했다.
- 한 부재의 여러 표면에 발화점이 붙으며 물체의 움직임을 따른다. 자동 연소 소모는 늦추고 반복 가열 시 소모를 추가한다. 12초 후에도 여러 발화점이 남는 회귀 테스트, 융해 시 불꽃·연소 상태 없음, 나이가 든 연기가 작아지지 않고 투명해지는 테스트를 통과했다.
- 화산은 클릭한 위치에 분화구를 만들고 세 갈래 용암 흐름을 전진시킨다. 보이는 경로에만 융해를 적용한다. 초기 용암이 아직 도착하지 않은 본관에 피해를 주지 않는 조건과, 도달 후 융해 적용을 검증했다. 브라우저에서 전진하는 용암 표면과 무늬를 확인했으며 콘솔 오류는 없었다. 용암은 경로 기반 게임 표현이다.
- 교내 도로와 코트 바닥만 파괴 가능한 판으로 전환했다. 주변 산·나무는 사용자 요청에 따라 배경으로 유지한다. 포장 분리와 파괴, 초기화 후 복구를 검증했다.
- 물리 파괴에 지면 굴착을 통합했다. 운석은 깊은 중심부와 넓고 얕은 충격파 영역을 남기며 가장자리와 깊이에 불규칙성을 준다. 지면 충돌은 같은 높이 함수를 표본화한 높이장으로 처리하고 렌더링은 기존 Marching Cubes 표면을 유지한다. 깊은 구덩이 낙하와 기초 지지력 상실 테스트가 통과했다.
